## 复现的问题

1. **P2 · 已倒地宠仍可通过固定槽位增加药次。** 初始化 A1 的在场宠，记录其倒地且仍占槽，再提交确认的 `USE_MEDICINE(actor_id="A_PET_1")`。账本由 0 增至 1。实例 ID 路径已有守卫，固定槽位路径还需解析已知在场实例。测试应同时保留中途录入时占槽情况未知的用法。见 [battle.py](../../src/battletracker/battle.py) 的 `_apply`。
2. **P2 · 构建器接受普通回放作为官方计数来源。** 在临时目录复制真实事件及其报告，将报告的 source_asset 和 source_sha256 替换为同一对中的普通回放资产 ID 和哈希。构建仍输出 16 条已映射变化并报告检查通过。应显式要求来源资产为已经配对的详细回放，并验证事件文件哈希。见 [build_dataset.py](../../tools/build_dataset.py) 的 `build`。
3. **P3 · Phase 2 验证对精度回退的约束有限。** 当前验收检查要求每类至少有一项正确，各区域至少有一次稳定输出。报告可以呈现实际漏读和错读，但没有参考读数质量的回归阈值。应先固定本场回归基线，再用新增比赛评估精度。见 [extract_counters.py](../../tools/extract_counters.py) 的 `main`。

Phase 3 当前只有同场开发数据。三条第 6 回合记录缺少普通录像对应范围。八条已对齐用药的施药者和一条额度变化的触发原因仍待确认。此次审核重建了现有产物并复现问题，尚未更改实现。
