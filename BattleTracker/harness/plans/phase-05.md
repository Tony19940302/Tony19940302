# Phase 5 · AI 增强实验

## 目标

按同一评估协议判断轻量模型对识别缺口的改进。

## 范围

对照传统特征与轻量时序模型，记录数据、训练和推理性能。

## 非目标

先锁定模型或用最终测试集调参。

## 依赖

Phase 4 基线、明确失败类型、可复现数据版本和验证集。

## 任务

定义训练预算、种子、统一指标；按需并行比较方案；记录失败案例；验证 ONNX 与原始模型输出一致。

## 验收标准

模型改进及其代价可比较，候选可重复训练及推理。

## 验证命令

`python tools/train_model.py --help`、`python tools/evaluate.py --help`、`python tools/verify.py --profile phase-05`。

## 已知风险

小样本过拟合、错误参考标签、移动端算子和性能差异。

## 完成证据

数据版本、训练参数、指标、ONNX 一致性及失败报告。 当前状态见 [阶段进度](../../docs/PROJECT_PROGRESS.md)。

## 当前实验 · temporal-linear-v1

输入为已复核普通回放片段中的 12 帧。画面缩小后裁取战区，提取三个时段的颜色均值和相邻帧变化。CPU 训练带 L2 正则的线性分类器，固定随机种子 42、300 步。输出为普通动作、用药、召唤的概率。最高概率低于 0.6 时列为未知。该实验先验证片段分类和导出流程，行动者识别仍由现有视觉基线承担。

同场片段和重复录像沿用比赛分组，未复核片段从训练中排除。开发试跑只用 development 组。正式模式要求 train 和 validation 分别含有不同的比赛，锁定的测试集留到最终测试。

补充素材后，先用 Phase 3 流程生成每场的人工复核索引，并合并各场索引。对同一批 validation 比赛固定回合标注与时间容差，分别运行 Phase 4 与增强流程。复用 `tools/evaluate.py` 的一对一指标，报告分类、归属、漏报和误报，并分别测量特征提取与推理耗时。当前片段分类模型使用人工给定的片段边界，其拟合分数不能与全录像事件指标直接比较。将模型接到 Phase 4 自动候选后再做该比较。

```powershell
python -m pip install -e ".[test,vision,experiment]"
python tools/verify.py --profile phase-05
python tools/train_model.py --index PATH_TO_GROUPED_INDEX
```

开发试跑通过。输入 12 段，包含用药 3、召唤 4、困难负样本 5。另 9 条未复核记录排除。38 项测试通过。ONNX 文件回读的权重在 NumPy 中重算与训练输出一致，最大概率差 0。Windows 本机 ONNX Runtime 1.24.4 与 1.22.1 都在 DLL 初始化失败，ONNX 原生校验与参考执行器也遇到访问冲突。Runtime 推理验证记为 SKIPPED。见 [验收报告](../reports/phase-05.json)和[实验元数据](../../outputs/phase-05/experiment.json)。

## 跨场对照 · 2026-11-19

训练使用雷绝阵对虎翼阵的 12 个复核片段。验证使用另一场龙飞阵对虎翼阵的 6 个独立复核片段，包括 1 次用药、2 次召唤、3 个干扰动作。同场录像按比赛归组。以原始播放时间戳对齐新录像，7 个拟合锚点和 7 个独立检查点的最大误差为 81 ms。实际用药者和目标缺乏独立证据时保留未知。见 [对齐报告](../../outputs/phase-05/alignment.json)和[标签审查](../reviews/dragon-tiger-label-review.md)。

对照传统规则基线、线性时序模型、轻量时序 CNN 和类别中心分类器。线性与 CNN 共同使用种子 42、300 步和固定训练配置。类别中心使用一次计算得到类别均值。冻结旧场的召唤光效模板，在新场手工定位画面槽位。三个模型仅审核规则给出的用药或召唤候选，低于 0.6 或分类不一致时保留为未知。评估使用相同的 500 ms 时间容差和一对一匹配。执行整段录像的检测，指标仅覆盖有人工参考的时间窗。

复跑环境安装 `pip install -e ".[test,vision,experiment,temporal,deployment]"`。旧 Windows 运行库导致初始化失败时，运行 `python tools/setup_runtime.py` 加载项目内固定版本的运行库。Phase 3 输出由对应验证入口生成，Phase 5 验证器重建分组索引、训练并执行整段对照。

全长约 398 秒，采样 4,970 帧。基线另有 51 个用药候选处于待核验范围。三个模型把全部用药候选转为未知，未补回用药或召唤漏报。整段对照无法支持模型增强带来有效收益，继续以传统基线作为默认实验入口。三种增强的 56 次候选分别增加约 42、39、38 秒采样和预处理，模型推理合计约 6、22、6 毫秒。各独立实验进程的最高采样工作集约 96–97 MiB，含解码器及运行库。三个模型在本机 ONNX Runtime CPU 上均通过原框架输出一致性校验。
